1 · How memory works: cells, words and addresses

1.1 The plain-language picture

A computer memory is a large shelf of numbered boxes. Each box holds a fixed number of bits. To read or write a box, the processor puts the box number on the address lines and either reads the data lines or drives new values onto them. The number of the box is its address; the number of bits in the box is the word size.

Formal vocabulary

A memory cell stores one bit. A word is the group of bits that the memory transfers in one access. A location (or addressable unit) is the smallest unit that has its own address. The address space is the set of all addresses. If a memory has n address lines, it can distinguish 2n locations. If each location is w bits wide, the total capacity is 2n × w bits.

1.3 Why the address/data distinction matters

The address lines choose which location; the data lines carry what is inside it. A memory can have many locations but a narrow word, or few locations but a wide word. For example, a 1M × 4 chip and a 512K × 8 chip both hold 4 Mbit, but the first has 20 address lines and 4 data lines, while the second has 19 address lines and 8 data lines. Always read the N × M specification before calculating.

  5. Box the answer with units. A number without units is incomplete.

2 · Memory hierarchy and performance parameters

2.1 Why a hierarchy exists

Fast memory is expensive and small; cheap memory is large and slow. A computer cannot afford to make all of its memory as fast as registers, and it cannot run efficiently if every access waits for a hard disk. The hierarchy is the engineering compromise: put a small amount of very fast memory close to the CPU, a larger but slower main memory behind it, and a very large but much slower secondary store behind that. The goal is to make the average access look fast by keeping the frequently used data near the top.

2.2 Locality of reference

The hierarchy works because real programs do not access memory uniformly. They show locality of reference:

  • Temporal locality: if an item was used recently, it is likely to be used again soon. A loop counter and a frequently called function are examples.
  • Spatial locality: if an address was used, nearby addresses are likely to be used soon. Array elements stored next to each other are the standard example.

Cache exploits both: it keeps recently used blocks (temporal) and fetches a whole block of neighbouring words on a miss (spatial). Paging exploits temporal locality by keeping recently used pages in memory. Without locality, a small cache would rarely contain the next item, and the hit ratio would collapse.

Everyday analogy

Your desk is the cache, the bookshelf is main memory, and the library basement is secondary storage. You keep the books you are using on the desk. When you need a new book, you fetch it once and put it on the desk, hoping you will need it again. The desk is small, so you occasionally remove a book to make room. This is exactly the cache replacement problem.

Access time versus cycle time — the distinction examiners look for

Access time is how long one operation takes. Cycle time is how soon you may start the next operation. If a memory answers in 50 ns but needs 10 ns to recover before the next request, the access time is 50 ns and the cycle time is 60 ns. DRAM also needs periodic refresh, which is one reason its cycle time is longer than its raw access time.

2.4 Cost, capacity and speed trade-off

Suppose a fast memory costs much more per bit than a slow one. Putting all storage in the fast technology would be unaffordable; putting all storage in the slow technology would be unusably slow. The hierarchy spends the budget where it buys the most performance: a small fast cache, a medium-speed main memory, and a large cheap secondary store. This is why the cost per bit falls as you go down the hierarchy, while capacity rises.

  4. Explain locality of reference as the reason the hierarchy works.
  5. Define access time, cycle time, transfer rate and capacity in one line each if the question asks for parameters.

3 · Primary and secondary memory; RAM and ROM

3.1 The classification

Primary memory is directly accessible to the CPU. It holds the instructions and data that are being executed now. It is fast, relatively expensive, and usually smaller than secondary storage. Secondary memory is not directly executed from; data must first be copied into primary memory. It is non-volatile, much larger and cheaper per bit, but slower.

3.2 RAM and ROM

RAM (Random Access Memory) is read/write, volatile, and used for programs and data in use. “Random access” means any location takes roughly the same time to reach, not that the contents are random. ROM (Read-Only Memory) is non-volatile and normally read-only during normal operation; it stores firmware such as the boot loader or BIOS/UEFI code. Modern ROM families can be programmed or erased under special conditions.

3.3 SRAM and DRAM

SRAM (Static RAM) stores a bit in a flip-flop — a small latch made from several transistors. As long as power is present, the bit stays put without refresh. It is fast but takes more area per bit, so it is expensive and has lower density. It is used for cache. DRAM (Dynamic RAM) stores a bit as charge on a tiny capacitor. The charge leaks away, so every cell must be refreshed periodically. A DRAM cell is much smaller and cheaper per bit, which is why main memory is DRAM, but it is slower and needs refresh circuitry.

Why “static” and “dynamic”?

SRAM is “static” because the stored value does not need to be refreshed while power is on. DRAM is “dynamic” because the charge is constantly leaking and must be restored by refresh cycles. The words describe the storage mechanism, not whether the memory is fast or slow in a particular computer.

4 · Memory expansion and chip organization

4.1 Why expansion is needed

A single memory chip is usually too small or too narrow for the memory system a processor needs. Engineers combine several chips to get more words (more addresses) or wider words (more bits per access). This is called memory expansion. The two directions are independent, and most real designs use both at once.

ExpansionGoalHow chips are connectedEffect
Word-size (width) expansionIncrease bits per wordChips share the same address and control lines; their data lines are connected side by side to different bit slices of the data bus.Data bus becomes wider; number of addressable locations stays the same.
Address (depth) expansionIncrease number of locationsChips share the data bus; a decoder uses higher address bits to select one chip (chip select).More addresses; word width stays the same.
total chips = (required locations ÷ chip locations) × (required word size ÷ chip word size)

Both factors must be whole numbers. If they are not, the required memory cannot be built exactly from identical chips.

Teacher problem 4 — memory expansion (Unit 4 problems, Problem 3)

Using 4K × 8 memory chips, design a memory system of 16K × 16. Find the number of chips required.

Question

Build 16K × 16 from 4K × 8 chips. How many chips are needed?

Solution

Step 1 — Expand the word size. The required word is 16 bits; each chip supplies 8 bits.

chips per word = 16 ÷ 8 = 2

Step 2 — Expand the number of locations. The required depth is 16K; each chip supplies 4K.

address groups = 16K ÷ 4K = 4

Step 3 — Multiply the two independent expansions.

total chips = 4 × 2 = 8

Step 4 — Check. Eight chips × 4K × 8 bits = 8 × 32K bits = 256K bits. The target is 16K × 16 = 256K bits. The capacities match.

Final Answer

8 chips: four address groups, each containing two chips in parallel.

Teacher problem 5 — ROM expansion (Unit 4 problems, Problem 5)

You have 2K × 8 ROM chips. Construct an 8K × 16 ROM. Find the number of ROM chips required.

4.2 Reading a chip diagram

In a chip diagram, the address pins receive A0…A(n−1), the data pins connect to the data bus, and the chip-select (CS) pin decides whether the chip responds at all. The read/write (R/W) pin decides the direction. When several chips share the data bus, only the selected chip may drive it; otherwise two chips would fight over the same wires. That is why a decoder is used: it turns the high-order address bits into exactly one active chip-select signal.

Common exam trap

Do not add the two expansion factors. They multiply because they are independent: four rows of two chips is eight chips, not six. Also, the number of address lines for the complete memory is log2(total locations), not the sum of the chips’ address lines.

4.3 Exam answer plan

  1. Write the target specification and the chip specification in N × M form.
  2. Compute the width factor (target M ÷ chip M).
  3. Compute the depth factor (target N ÷ chip N).
  4. Multiply for the total chip count.
  5. Describe the connections: common address lines, decoder for chip select, data slices for width.
  6. Check total bits before and after expansion.

5 · Virtual memory I: paging

5.1 Why virtual memory exists

Programs are written as if they own a large, contiguous address space. The physical RAM is smaller than the sum of all running programs, and several programs must coexist without being able to read or overwrite each other. Virtual memory solves this by giving each program its own virtual address space and translating every virtual address into a physical address at run time. The translation is done by the MMU (Memory Management Unit) using tables prepared by the operating system.

Virtual memory gives four practical benefits:

  • Large address space: a program can use more virtual memory than the physical RAM, because inactive pages can live on disk or SSD.
  • Isolation and protection: one process cannot name another process’s physical memory unless the OS deliberately maps it.
  • Simpler loading: a program does not need a single contiguous physical region.
  • Sharing: several processes can map the same physical page read-only, for example a shared library.

5.2 The paging idea

Paging divides the virtual address space into fixed-size pages and physical memory into fixed-size frames. A page and a frame are the same size. Any page can be placed in any free frame, so physical memory does not need to be contiguous. The OS keeps a page table for each process. Each page-table entry (PTE) maps a virtual page number to a physical frame number and stores control bits such as valid, dirty and permission bits.

5.3 Splitting the address

virtual address bits = page-number bits + offset bits
offset bits = log2(page size in bytes)
page-number bits = virtual address bits − offset bits
number of virtual pages = 2page-number bits = virtual address space ÷ page size
number of frames = physical memory size ÷ page size
frame-number bits = log2(number of frames)

The offset is copied unchanged. Only the page number is translated. This is the single most important idea in paging: the low bits stay, the high bits are replaced.

5.4 The translation procedure

  1. Extract the page number and offset from the virtual address using the page size.
  2. Use the page number as an index into the page table.
  3. Read the PTE. If the valid bit is 0, a page fault occurs and the OS handles it.
  4. Take the frame number from the PTE.
  5. Concatenate the frame number with the original offset to form the physical address.

5.5 Page-table size

A single-level page table has one entry per virtual page. If each entry is 4 bytes, the table size is:

page-table size = number of virtual pages × size of one PTE

For the previous example, 220 entries × 4 bytes = 4 MiB per process. That is often too much, so real systems use multi-level page tables: the upper levels map only the portions of the address space that are actually in use. You do not need to design a multi-level table for this syllabus, but you should be able to explain why a flat table can be large.

TLB — a small cache for translations

A TLB (Translation Lookaside Buffer) stores recent VPN-to-frame mappings. A TLB hit avoids reading the page table from memory; a TLB miss causes a page-table walk. The TLB is a practical application of associative memory (Section 12). The syllabus does not require TLB design, but the term is useful in a virtual-memory answer.

6 · Virtual memory II: segmentation

6.1 The segmentation idea

Segmentation divides a program into variable-sized logical units: a code segment, a data segment, a stack segment, a heap segment, a shared library segment. Each segment has a number, a base (its starting physical address) and a limit (its length). The CPU generates a logical address as a pair (segment number, offset). The MMU looks up the segment table, checks that the offset is within the limit, and adds the base to the offset.

physical address = segment base + offset    provided offset < limit
if offset ≥ limit → segmentation fault (invalid address)

The limit check is not optional. It is what stops a program from reading past the end of its segment into another program’s data. This is a protection mechanism, not just arithmetic.

6.2 The translation procedure

  1. Read the segment number and offset from the logical address.
  2. Use the segment number to index the segment table.
  3. Read the base and limit for that segment.
  4. If offset ≥ limit, raise a segmentation fault and stop.
  5. Otherwise compute physical address = base + offset.

7 · Cache memory: concept and performance

7.1 The problem cache solves

A modern processor can execute several instructions in the time it takes main memory to answer one request. If every instruction and operand had to come from DRAM, the processor would spend most of its life waiting. Cache memory is a small, fast SRAM array placed between the CPU and main memory. It holds copies of recently used blocks. When the CPU asks for data, the cache checks whether it already has the block. If it does, the access is a hit and completes at cache speed. If it does not, a miss occurs, the block is fetched from main memory, and the CPU waits for the slower access.

Formal definition

A cache is a small, high-speed memory that stores copies of blocks from a larger, slower memory, together with tags that identify which block each copy came from. It exploits temporal and spatial locality to make the average access time close to the cache access time even though most data still lives in main memory.

7.4 Hit ratio and average access time

Let h be the hit ratio, Tc the cache access time, and Tm the main-memory access time. There are two common conventions. Read the question carefully and state which one you use.

Convention A — simultaneous lookup (cache and memory checked together)

On a hit, the access takes Tc. On a miss, the access takes Tm (the memory access replaces the cache access, or the cache lookup is overlapped with it).

Tavg = h·Tc + (1 − h)·Tm
Convention B — hierarchical lookup (cache first, then memory on a miss)

On a miss, the CPU first spends Tc discovering the miss, then spends Tm fetching the block. The total miss time is Tc + Tm.

Tavg = h·Tc + (1 − h)(Tc + Tm) = Tc + (1 − h)·Tm

For two cache levels plus main memory, the same logic extends. If h1 is the L1 hit ratio and h2 is the L2 hit ratio among L1 misses, then the fraction of accesses that reach main memory is (1 − h1)(1 − h2). A hierarchical average is:

Tavg = TL1 + (1 − h1)·TL2 + (1 − h1)(1 − h2)·Tmain

This form treats each T as the additional access time at that level. Some textbooks instead use “miss penalty” terms; both are valid if the definition is stated. Do not mix the two conventions in one calculation.

AMAT = 0.90(2) + 0.095(12) + 0.005(112)
= 1.8 + 1.14 + 0.56

stall cycles per instruction = m × r × P

8 · Cache mapping techniques

8.1 The placement problem

Main memory is much larger than cache, so a cache block must be a copy of one of many main-memory blocks. Cache mapping is the rule that decides where a main-memory block may be placed in the cache, and how the cache recognises which block it currently holds. There are three standard rules:

TechniquePlacement ruleAddress fieldsSearch
Direct mappingBlock B can go to exactly one line: B mod L, where L is the number of cache lines.Tag | line | offsetOne tag comparison.
Fully associativeBlock B can go to any cache line.Tag | offsetCompare the tag with every line in parallel.
Set associativeBlock B can go to any line in exactly one set: B mod S, where S is the number of sets.Tag | set | offsetCompare the tag with the N ways of the selected set.

8.2 Direct mapping

In direct mapping, the cache line is fixed by the block number. The low bits of the block number select the line, and the remaining high bits become the tag. The advantage is simple, cheap hardware: one comparator and one multiplexer. The disadvantage is conflict misses: two frequently used blocks that map to the same line keep evicting each other even if the rest of the cache is empty.

cache line = block number mod number of cache lines
block number = memory address ÷ block size
tag = block number ÷ number of cache lines

8.3 Fully associative mapping

In fully associative mapping, any block can go into any line. There is no line number in the address, so the address has only a tag and an offset. On every access, the cache compares the incoming tag with the tag of every line in parallel. This removes conflict misses completely, but it needs a comparator per line and a priority encoder to choose the matching line. It is expensive for large caches, which is why it is used for small structures such as TLBs.

8.4 Set-associative mapping

Set-associative mapping is the compromise. The cache is divided into S sets, each containing N lines (an “N-way” cache). A block maps to exactly one set, but within that set it can occupy any of the N ways. The hardware compares N tags in parallel, not all lines. A 4-way set-associative cache with 64 lines has 16 sets; a block maps to one of those 16 sets and can sit in any of its 4 lines.

8.5 The universal method for mapping numericals

  1. Find the total address bits. If main memory is given in bytes, total bits = log2(memory size in bytes). If it is given in blocks, total bits = log2(number of blocks) + log2(block size).
  2. Find the offset bits. offset = log2(block size in bytes or words). Use the same unit as the address.
  3. Find the number of lines or sets. Lines = cache size ÷ block size. Sets = lines ÷ associativity.
  4. Find the index/set bits. index = log2(lines) for direct mapping; set = log2(sets) for set-associative; no index for fully associative.
  5. Find the tag bits. tag = total address bits − index bits − offset bits.
  6. Check. tag + index + offset must equal the total address bits. For fully associative, tag + offset = total.
The one formula that prevents most errors
tag bits = total address bits − index (or set) bits − offset bits

If you remember only this, you can recover the fields in any mapping question. The offset is fixed by the block size; the index is fixed by the number of lines or sets; the tag is whatever remains.

9.1 The coherence problem

In a multiprocessor system, each processor may have its own cache. A shared variable can therefore exist in several places at once: in main memory and in one or more caches. If one processor writes a new value, the other copies become stale. A program running on another processor may then read an old value. Cache coherence is the set of rules and mechanisms that prevent this.

Teacher example — two processors and a shared variable (Unit 4 problems, Problem 19)

Two processors P1 and P2 have separate caches. Initially X = 50, and both caches contain X = 50. P1 changes X to 75. P2 reads X. What value can P2 incorrectly obtain if cache coherence is not maintained? What should P2 obtain after applying a coherence protocol?

Question

Both caches hold X = 50. P1 writes 75. What can P2 read without coherence, and what should it read with coherence?

Solution

Without coherence: P1’s write updates P1’s cache (and possibly not main memory, if the cache is write-back). P2’s cache still holds 50. P2 can therefore read the stale value 50.

With coherence: P1’s write must either update P2’s copy or invalidate it. If P2’s copy is invalidated, P2’s next read misses and fetches 75 from P1’s cache or from memory after the write-back. P2 must read 75.

Final Answer

Without coherence: P2 may read 50. With coherence: P2 must read 75.

9.3 The MESI states

MESI names four states for a cache line: Modified, Exclusive, Shared and Invalid. The state records two things: whether the line is valid, and whether the copy is clean (same as memory) or dirty (newer than memory).

These are the standard simplified transitions. Real implementations add details such as whether the data is supplied by the owner or by memory, and whether a write-back is needed. For an exam, the table above is the expected level.

Why “Exclusive” is useful

If a cache loads a block and no other cache has it, the line is marked Exclusive. A later write can then change it to Modified without sending an invalidation on the bus, because there is no other copy to invalidate. This is an optimisation, not a separate coherence mechanism.

10 · Interleaved memory

10.1 Why interleave

DRAM is slow relative to the CPU, and one memory bank can serve only one request at a time. Interleaving spreads consecutive addresses across several banks so that different banks can serve different requests in parallel. While bank 0 is busy, the memory controller can start a request to bank 1, then bank 2, and so on. The result is higher throughput for sequential accesses.

11 · Associative memory

11.1 The idea

Ordinary RAM is address-addressed: you supply an address and get the word at that address. Associative memory, also called content-addressable memory (CAM), is content-addressed: you supply a key (a data pattern) and the memory tells you whether that pattern is stored, and where. It is a hardware search engine. Every stored word is compared with the key in parallel, so the search takes one clock cycle regardless of the number of words.

Formal definition

An associative memory is a memory array with comparison logic attached to every word. The argument register holds the search key, the key register (mask register) selects which bit positions participate in the comparison, and the match register has one bit per stored word. After a search, the match bits of all matching words are set to 1.

11.2 Capacity and search

capacity = number of words × bits per word
number of parallel comparisons = number of words (one comparator per word)

The number of comparisons is not divided by a clock rate in the ideal model: all words are compared simultaneously. That is why associative memory is fast for search but expensive per bit. Each cell needs storage plus comparison logic, and the match lines need priority resolution.

PYQ 3 · Virtual memory, paging and segmentation · 8 marks
MUSA Paper Set I Q4(a); MUSA QB Q10 — MUSA practice material, not a verified University paper
Question

Explain virtual memory in detail. Describe paging and segmentation with neat diagrams.

Solution

Virtual memory lets a program use a larger address space than the physical RAM. The program works with virtual addresses, and the memory management unit (MMU) translates them to physical addresses using tables. Only the parts in use are kept in RAM; the rest stays on disk, and a missing part is fetched on a page fault. Benefits: programs larger than RAM, isolation between processes, and simple memory allocation.

Paging. Virtual memory is split into equal fixed-size pages and physical memory into frames of the same size. A virtual address is page number | offset. The page table maps each page number to a frame number, and the physical address is frame number | offset. There is no external fragmentation, only a little internal fragmentation in the last page. A TLB caches recent translations.

Segmentation. The program is split into variable-size logical segments (code, data, stack). A virtual address is segment number | offset. The segment table stores each segment's base and limit; the offset is checked against the limit and added to the base. It matches the programmer's view and eases sharing and protection, but causes external fragmentation.

PYQ 6 · Interleaved and associative memory · 5 marks

Question

Interleaved memory. Main memory is divided into several independent modules (banks). Search is very fast (one cycle) but each cell needs comparison logic, so it is expensive and small. Used in TLBs and cache tag lookup. PYQ 7 · Cache memory and cache coherency · 5 marks
MUSA Paper Set I Q6(b); MUSA QB Q24(iii) — MUSA practice material, not a verified University paper
Question

Write a short note on cache memory and on cache coherency, and the techniques to resolve it.

Solution

Cache memory. A small, fast SRAM holding recently used blocks. Hit ratio h and miss penalty give the average access time: tavg = h·tcache + (1 − h)·tmemory. It works because of temporal and spatial locality. Levels L1, L2 and L3 trade speed for size.

Cache coherency. In a multiprocessor each CPU has its own cache. If two caches hold X = 50 and one writes 75, the other still reads the stale 50. Coherence means every processor sees a consistent value for each shared location.

  • Write policies: write-through updates memory on every write; write-back delays it until eviction.
  • Snooping: every cache watches the shared bus; on a write, other copies are invalidated (write-invalidate) or updated (write-update).
  • MESI protocol: each line is Modified, Exclusive, Shared or Invalid; a write to a Shared line invalidates other copies.
  • Directory-based: a directory records which caches hold each block (for large systems).
Final Answer

Cache memory speeds up access using locality; coherency keeps shared copies consistent using snooping with write-invalidate or update, MESI, or a directory. The coherence problem and the MESI state diagram are drawn in Figures 14 and 15 (Section 9).

15 · Answer key

Mark your work against the working, not only the final number. A correct final answer with a wrong method will not earn full marks in the exam.

Answers

A · Basic

  1. 13 address lines, 8 data lines, 8 KB.
    8K = 23 × 210 = 213 locations, so 13 address lines. The word is 8 bits, so 8 data lines. Capacity = 213 × 8 = 216 bits = 213 bytes = 8 KB.
  2. 4 chips.
    Depth factor = 32K ÷ 8K = 4. Width factor = 8 ÷ 8 = 1. Total = 4 × 1 = 4. Check: 4 × 8K × 8 = 32K × 8. Correct.
  3. 20 ns.
    EAT = 0.9(10) + 0.1(10 + 100) = 9 + 11 = 20 ns. A miss pays the cache lookup and then the memory access.
  4. 13 offset bits, 19 page-number bits, 524,288 pages.
    8 KB = 213, so offset = 13. Page bits = 32 − 13 = 19. Pages = 219 = 524,288. Check: 19 + 13 = 32.
  5. (a) Valid, physical address 2599. (b) Invalid — segmentation fault.
    (a) 599 < 600, so physical = 2000 + 599 = 2599. (b) 600 ≥ 600, so the limit check fails; no physical address is produced. Note that the limit is an exclusive upper bound.
  6. Bank 1.
    Low-order interleaving: bank = address mod 4 = 13 mod 4 = 1.

B · Intermediate

  1. 11 offset bits, 32 virtual pages, 256 frames, 8 frame-number bits.
    2 KB = 211 ⇒ offset 11. VPN bits = 16 − 11 = 5 ⇒ 25 = 32 pages. 512 KB = 219 bytes ⇒ frames = 219 ÷ 211 = 28 = 256 ⇒ 8 frame bits. Check: 8 + 11 = 19 physical address bits.
  2. 1024 lines; offset 5, index 10, tag 17.
    32 KB = 215 B, 32 B = 25 B. Lines = 215 ÷ 25 = 210 = 1024. Offset = 5. Index = 10. Tag = 32 − 10 − 5 = 17. Check: 17 + 10 + 5 = 32.
  3. 4096 lines, 2048 sets; set 11, offset 4, tag 17.
    64 KB ÷ 16 B = 216 ÷ 24 = 212 = 4096 lines. Sets = 4096 ÷ 2 = 2048 = 211. Offset = log2 16 = 4. Tag = 32 − 11 − 4 = 17. Check: 17 + 11 + 4 = 32.
  4. 1.7 ns.
    AMAT = 1 + (0.05)(8) + (0.05)(0.10)(60) = 1 + 0.4 + 0.3 = 1.7 ns. The last term is the 0.5% of accesses that miss both caches.
  5. Tag = 1616 (22), line = 3A16 (58), offset = 5.
    256 KB = 218 ⇒ 18 address bits. Offset = log2 16 = 4. Lines = 8 KB ÷ 16 B = 512 ⇒ index = 9. Tag = 18 − 9 − 4 = 5.
    2C3A516 = 10 1100 0011 1010 01012. Tag = 101102 = 1616 = 22. Line = 0 0011 10102 = 3A16 = 58. Offset = 01012 = 5.
    Check: 22 × 8192 + 58 × 16 + 5 = 180,224 + 928 + 5 = 181,157 = 2C3A516. Correct.
  6. 400 ns without interleaving, 50 ns with ideal 8-way interleaving, speed-up 8.
    Serial: 8 × 50 = 400 ns. Parallel: 50 ns. Speed-up = 400 ÷ 50 = 8. Real hardware will be slower because of arbitration and bus transfer time.
  7. 16,384 bits = 2 KB; 512 parallel comparisons.
    Capacity = 512 × 32 = 16,384 bits. In bytes = 16,384 ÷ 8 = 2048 B = 2 KB. One comparator per word ⇒ 512 comparisons in parallel.

C · Advanced

  1. 220 entries; 4 MiB.
    4 KB = 212 ⇒ offset 12; VPN bits = 32 − 12 = 20 ⇒ 220 = 1,048,576 entries. Size = 220 × 4 B = 222 B = 4 MiB. This is per process, which is why multi-level page tables exist.
  2. 2048 lines, 512 sets; set 9, offset 6, tag 25.
    128 KB ÷ 64 B = 217 ÷ 26 = 211 = 2048 lines. Sets = 2048 ÷ 4 = 512 = 29. Offset = log2 64 = 6. Tag = 40 − 9 − 6 = 25. Check: 25 + 9 + 6 = 40.
  3. h = 0.9 (90%).
    AMAT = Tc + (1 − h)Tm ⇒ 40 = 20 + (1 − h)(200) ⇒ (1 − h) = 20 ÷ 200 = 0.1 ⇒ h = 0.9.
  4. 4 chips.
    Depth factor = 64K ÷ 16K = 4; width factor = 8 ÷ 8 = 1 ⇒ 4 chips. With 16K = 400016 addresses per chip:
    Chip 0: 0000H–3FFFH  ·  Chip 1: 4000H–7FFFH  ·  Chip 2: 8000H–BFFFH  ·  Chip 3: C000H–FFFFH.
    A 2-to-4 decoder driven by A14 and A15 selects one chip at a time.
  5. All four accesses hit bank 0; total 400 ns; ideal consecutive-address time would be 100 ns.
    Bank = address mod 4: 0 mod 4 = 0, 4 mod 4 = 0, 8 mod 4 = 0, 12 mod 4 = 0. Every access goes to bank 0, so there is no parallelism and the time is 4 × 100 = 400 ns (speed-up 1). Four consecutive addresses 0, 1, 2, 3 would go to banks 0, 1, 2, 3 and finish in one access time, 100 ns. This is the classic stride conflict of low-order interleaving.
  6. Model written answer. A fully associative cache allows any block in any line, so the address does not need to name a line; the hardware compares the tag against every line. The index field exists only to select a line or set before comparison, so with no selection there is no index. The tag must therefore carry all the block-number bits, and tag + offset = total address bits. A TLB holds a small number of page-table entries and must answer in one cycle; fully associative or highly set-associative placement removes conflict misses for the few entries it can hold, and the comparator cost is acceptable because the TLB is small. The trade-off is hardware cost per entry, which is why large data caches use lower associativity.
  7. Model written answer. Paging divides the address space into fixed-size pages; segmentation divides it into variable-size logical segments. A paging address is page number + offset, and the table entry holds a frame number plus valid, dirty and permission bits. A segmentation address is segment number + offset, and the table entry holds a base and a limit; the hardware checks offset < limit before adding the base. Paging suffers internal fragmentation in the last page; segmentation suffers external fragmentation between segments. Paging is invisible to the programmer; segmentation is visible because segments match logical program units, which makes sharing and protection natural. Real systems combine them (segments that are themselves paged) to get logical protection boundaries with fixed-size allocation.

16 · Common mistakes

Errors that cost marks, and the fix

MistakeWhy it is wrongCorrect approach
Writing 1 KB = 1000 bytesMemory capacity and page size use powers of two.1 KB = 210 = 1024 bytes; convert to a power of two before taking logarithms.
Confusing address lines with data linesThey answer different questions: which location, and how wide.Address lines = log2(locations); data lines = bits per location.
Adding expansion factorsDepth and width are independent dimensions.Total chips = depth factor × width factor.
Using cache size as the number of linesA line holds a whole block.Lines = cache size ÷ block size.
Omitting the offset when computing the tagThe tag is only the remaining high bits.Tag = total address bits − index/set bits − offset bits.
Putting an index field in a fully associative cacheNothing selects a line before the comparison.Tag + offset = total bits; compare the tag with every line.
Using lines instead of sets for the index in an N-way cacheThe index chooses a set, not a line.Set bits = log2(lines ÷ N).
Changing the offset during paging translationThe offset is the position inside the page and does not change.Replace only the page number with the frame number; copy the offset unchanged.
Using the physical address size to count virtual pagesVirtual pages come from the virtual address; frames come from physical memory.Pages = virtual space ÷ page size; frames = physical space ÷ page size.
Skipping the limit check in segmentationThe check is the protection mechanism.If offset ≥ limit, report a segmentation fault; do not compute base + offset.
Using address mod n for high-order interleavingHigh-order interleaving uses the high address bits.Low-order: bank = address mod n. High-order: bank = address ÷ bank size.
Claiming the full speed-up n in every real interleaved systemArbitration, bus transfer and bank conflicts add time.n is the ideal upper bound; state the assumption when you use it.
Mixing the two AMAT conventionsOne counts the cache lookup on a miss; the other does not.State the formula first: hTc + (1 − h)Tm, or Tc + (1 − h)Tm.
Writing a number with no unit“13” could be ns, bits or lines.Box the answer with its unit: 13 ns, 13 bits, 13 lines.

17 · Last-minute revision sheet

Ten minutes before the paper

Capacity and lines. N × M means N locations of M bits. Address lines = log2 N. Data lines = M. Capacity = N × M bits; divide by 8 for bytes, by 1024 for KB, by 220 for MB.

Expansion. Total chips = (target depth ÷ chip depth) × (target width ÷ chip width). Check total bits before and after.

Paging. Offset = log2(page size). VPN bits = VA bits − offset. Pages = virtual space ÷ page size. Frames = physical space ÷ page size. Frame bits = log2 frames. The offset never changes. Page-table size = entries × PTE size.

Segmentation. Check offset < limit first. If valid, physical = base + offset. If not, segmentation fault.

Cache fields. Offset = log2(block size). Lines = cache size ÷ block size. Index = log2 lines (direct) or log2(lines ÷ N) (N-way). Tag = total − index − offset. Fully associative has no index.

Cache performance. h = hits ÷ accesses. Hierarchical EAT = hTc + (1 − h)(Tc + Tm) = Tc + (1 − h)Tm. Simultaneous EAT = hTc + (1 − h)Tm. Two levels: add (1 − h1)TL2 and (1 − h1)(1 − h2)Tmain.

Interleaving. Low-order: bank = address mod n. High-order: bank = address ÷ bank size. Ideal speed-up = n; real speed-up is lower.

Associative memory. Capacity = words × bits per word. Comparisons = one per word, all in parallel. Argument register holds the key; mask/key register selects bits; match register records hits.

MESI. Modified (only copy, dirty), Exclusive (only copy, clean), Shared (clean, may be in several caches), Invalid (no valid copy). Write to Shared → invalidate others → Modified. Read of Modified → owner supplies data.

One-line definitions to have ready: locality of reference; hit ratio; miss penalty; virtual memory; page fault; TLB; write-through vs write-back; direct vs associative vs set-associative; cache coherence; snooping vs directory.
